# Demo plan and specs: consolidated C-level reporting (CRM + Excel + other sources)

Status: DRAFT, waiting for Yannick's approval. Nothing is built yet.
Source job: [Data Analyst for Consolidated Reporting](https://www.upwork.com/jobs/~022115416503170118395) (id 2115416503170118395, Poland, hourly $15–50, posted 28 Oct 2026 13:14 Europe/Zurich).

## 1. What the client asked for (their words)
- "Consolidate data from our CRM, Excel files, and other sources into one centralized location."
- "Reliable reports that provide accurate insights for our C-level managers."
- "Organize the data, validate its accuracy, and build clear reports that support decision-making."
- "Experience handling multiple data sources and delivering structured reporting."

## 2. The demo in one line
A refreshable Excel workbook that pulls three messy sources (a CRM export, two sales/finance Excel files with different layouts, and a CSV target sheet), cleans and links them with Power Query into one model, runs visible data-quality checks, and shows a one-page executive dashboard. All data is synthetic (fictional company), generated by a script.

## 3. Requirements and how each is tested

| # | Requirement | Source | How it is tested | Pass threshold |
|---|---|---|---|---|
| R1 | Pull CRM, Excel and one other source into one place | Post | Refresh All on clean copies of the 3 sources; count tables loaded | All 3 sources load; 0 refresh errors |
| R2 | Different layouts mapped to one standard schema | Post ("multiple data sources") | Input spec lists every source column → target column; script checks every target column is filled from a mapped source | 100% of target columns mapped; unmapped source columns listed on a sheet |
| R3 | Data accuracy validated | Post | Reconciliation sheet: row counts and revenue totals per source vs. consolidated model | Counts and totals match exactly (0.00 difference) |
| R4 | Duplicates and broken links caught, not silently dropped | Business standard | Seeded test data with 15 known issues (duplicate customers, deal with unknown customer id, bad dates, text in amount field, currency mix) | All 15 seeded issues appear on the Exceptions sheet; 0 false positives on the clean file |
| R5 | Customer matching across CRM and Excel | Business standard | Fuzzy-ish key rules (trimmed, case-folded name + country, then id); compare to an answer key | ≥ 98% correct matches on the 300-row test set; every non-match listed |
| R6 | Clear C-level report | Post | One-page dashboard: revenue vs. target, pipeline by stage, top 10 customers, month trend; a non-analyst reviewer answers 5 set questions from it | 5/5 answered correctly in under 2 minutes |
| R7 | Figures on the dashboard tie back to the data | Business standard | Python reference script recomputes the 6 headline KPIs independently | Every KPI equals the Python figure to the cent |

| R10 | Someone else can run it | Business standard | One-page README and a 3-minute handover note; a fresh reader follows it | Reader refreshes and finds the exceptions without help |

## 4. Stack and why
- **Excel + Power Query**: the client already lives in Excel files, so no new licence or tool to adopt, and refresh is one click.
- **Power Query input spec sheet**: makes the source-to-target mapping visible, which is what lets C-level trust the numbers.
- **Python (pandas) reference script + pytest**: independent recomputation of KPIs and the seeded-issue checks, so accuracy is proven, not claimed.
- **Excel dashboard (PivotCharts / simple charts)**: opens anywhere; a Power BI version is an optional later step.

## 5. Build steps and time (about 6–8 hours)
1. Generate synthetic sources (CRM CSV, two Excel layouts, targets CSV) plus answer key and seeded issues: 1.5 h
2. Power Query: staging queries per source, standard schema, customer match, model tables: 2 h
3. Checks and Exceptions sheets, reconciliation: 1 h
4. Executive dashboard page: 1 h
5. Python reference + pytest (R3, R4, R5, R7), messy-input run (R9): 1.5 h
6. README, screenshots, handover note, realism-gate review: 1 h
